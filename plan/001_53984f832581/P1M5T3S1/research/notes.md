# Research Notes — P1.M5.T3.S1: Config-gated WS2812 mirror (GP16)

All findings below were verified DIRECTLY on this machine against the installed
toolchain during this research session (no web claims taken on faith).

## 1. CRITICAL FINDING — the assumed `libraries/WS2812` does NOT exist

- `architecture/external_deps.md` §5 claims: "arduino-pico bundles a PIO-based
  `WS2812` library (`libraries/WS2812`): `WS2812(pin, count, pio)` with
  `begin()` / pixel-set / `show()` methods."
- **The installed core has NO such library.** Verified:
  - Installed core: `~/.platformio/packages/framework-arduinopico`, git
    `describe` → **arduino-pico 5.4.1** (PlatformIO package `1.50401.0`).
  - `ls libraries/` → 70 libraries, **no WS2812** (checked casing-insensitively).
  - `grep -ri ws2812` over `libraries/` and `cores/rp2040/` → zero hits.
  - Full (non-shallow) git history: `git log --all --diff-filter=A --
    "libraries/WS2812*"` → never added.
- The item contract itself hedged: "verify exact method names against the
  installed core version at implementation". Verified: the class does not
  exist in ANY version up to 5.4.1 — the external_deps.md URL was a salvaged
  partial-research artifact (its own method note admits subagents died).
- A PRP that says `#include <WS2812.h>` / `WS2812 strip(...)` **fails to
  compile**. This research session found and verified the correct path (§2–§4).

## 2. The correct dependency-free path (ALL pieces ship inside the core)

Three verified facts make a zero-new-dependency PIO driver possible:

1. **Canonical WS2812 PIO program ships in the core's bundled pico-sdk**:
   `~/.platformio/packages/framework-arduinopico/pico-sdk/src/rp2_common/
   pico_status_led/ws2812.pio` (added upstream 2025; constants T1=3/T2=3/T3=4
   "selected for broad compatibility with WS2812, WS2812B, and SK6812").
   Its sibling `status_led.c` is the official usage example
   (`ws2812_program_init(pio, sm, off, pin, 800000, false)` +
   `pio_sm_put_blocking`, GRB word `GREEN<<24 | RED<<16 | BLUE<<8`).
2. **The core exposes a public PIO loading helper**: `cores/rp2040/PIOProgram.h`
   — class `PIOProgram(const pio_program_t*)` with
   `bool prepare(PIO* pio, int* sm, int* offset, int gpio_start, int gpio_cnt)`.
   House usage INSIDE the core: `Tone.cpp` (static `PIOProgram _tone2Pgm
   (&tone2_program); ... prepare(...); tone2_program_init(...)`) and
   `SerialPIO.cpp`. It handles SM claim + program load + reuse across both
   PIO blocks, mutex-protected.
3. **Precedent for embedding pre-assembled programs**: the core itself ships
   `tone2.pio.h`, `ccount.pio.h`, `pio_uart.pio.h` — autogenerated pioasm
   headers compiled as C++. A sketch can embed the same shape.

**This satisfies PRD §3's "must also build in Arduino IDE with just the core
installed"** — no lib_deps, no Library Manager, no external files. Alternatives
rejected: Adafruit_NeoPixel (external dep → violates "just the core"; adds
lib to both build systems); bit-banging (blocking + fragile timing).

## 3. Verified pioasm output (assembled on this machine)

Ran the PlatformIO-installed pioasm (the same tool family the core is built
with) on the canonical program:

```
~/.platformio/packages/tool-pioasm-rp2040-earlephilhower/pioasm \
  -o c-sdk ws2812.pio ws2812.pio.h
```

Result (complete, verbatim — this is what gets embedded in the sketch):

```c
#define ws2812_wrap_target 0
#define ws2812_wrap 3
#define ws2812_pio_version 0
#define ws2812_T1 3
#define ws2812_T2 3
#define ws2812_T3 4
static const uint16_t ws2812_program_instructions[] = {
    0x6321, //  0: out    x, 1            side 0 [3]
    0x1223, //  1: jmp    !x, 3           side 1 [2]
    0x1200, //  2: jmp    0               side 1 [2]
    0xa242, //  3: nop                    side 0 [2]
};
static const struct pio_program ws2812_program = {
    .instructions = ws2812_program_instructions,
    .length = 4,
    .origin = -1,
    .pio_version = ws2812_pio_version,
};
static inline pio_sm_config ws2812_program_get_default_config(uint offset) {
    pio_sm_config c = pio_get_default_sm_config();
    sm_config_set_wrap(&c, offset + ws2812_wrap_target, offset + ws2812_wrap);
    sm_config_set_sideset(&c, 1, false, false);
    return c;
}
#include "hardware/clocks.h"
static inline void ws2812_program_init(PIO pio, uint sm, uint offset, uint pin, float freq, bool rgbw) {
    pio_gpio_init(pio, pin);
    pio_sm_set_consecutive_pindirs(pio, sm, pin, 1, true);
    pio_sm_config c = ws2812_program_get_default_config(offset);
    sm_config_set_sideset_pins(&c, pin);
    sm_config_set_out_shift(&c, false, true, rgbw ? 32 : 24);
    sm_config_set_fifo_join(&c, PIO_FIFO_JOIN_TX);
    int cycles_per_bit = ws2812_T1 + ws2812_T2 + ws2812_T3;
    float div = clock_get_hz(clk_sys) / (freq * cycles_per_bit);
    sm_config_set_clkdiv(&c, div);
    pio_sm_init(pio, sm, offset, &c);
    pio_sm_set_enabled(pio, sm, true);
}
```

(One line dropped vs. the raw generator output: the `#if !PICO_NO_HARDWARE`
guards — irrelevant/noise in a sketch; the core's own tone2.pio.h keeps them,
either form compiles. `used_gpio_ranges` field is `#if PICO_PIO_VERSION > 0`
only — RP2040 is PIO v0, omitted. `pio_version` field exists unconditionally
on this SDK version; designated initializer in declaration order is required
and used.)

## 5. Pin + electrical facts (verified locally)

- `variants/waveshare_rp2040_zero/pins_arduino.h` (installed core):
  `#define PIN_NEOPIXEL (16u)` — the board definition's own name for the
  onboard WS2812 data pin. USE IT instead of a literal 16 (config.h §8 has no
  RGB pin constant and is FROZEN; PIN_NEOPIXEL is the board-provided canonical
  constant, same trick as BOOTSEL).
- PRD §2.1: GP16 = onboard WS2812, firmware-only, powered from 3V3 rail →
  brightness cap RGB_BRIGHTNESS=60/255 is an LDO-budget constraint (PRD §2.2).
- RP2040-Zero runs clk_sys = 125 MHz (arduino-pico default, no overclock) →
  div = 125e6/(800e3×10) = 15.625 → bit = 10 cycles = 1.25 µs (800 kHz ✓).
  `clock_get_hz(clk_sys)` in the init adapts if that ever changes.
- PIO capacity: RP2040 has 2 PIO blocks × 4 SMs; this sketch uses exactly ONE
  SM and 4 instruction slots; tone/SerialPIO unused. `prepare()` failure is
  near-impossible but MUST be handled (mirror silently disabled; external
  LED on GP14 unaffected — fail-safe by design).
- WS2812 latch/reset time >50 µs (80 µs conservative): change-driven updates
  are ≥100 ms apart (fastest pattern edge = ACK_BLINK_MS) — 3 orders of
  magnitude of margin; no explicit wait needed. WS2812 is latching (holds
  color without refresh), so "write only on change" is not just optimization.
- FIFO: `pio_sm_put_blocking` blocks only if the 8-deep joined TX FIFO is
  full; the SM drains a 24-bit frame in 30 µs while we push at most one word
  per ≥100 ms → can never block the loop (PRD §10 non-blocking invariant).

## 6. Data format (from official status_led.c, verified)

- RGB WS2812 (not RGBW): autopull threshold 24, shift MSB-first (shift_right
  = false) → the 32-bit pushed word is **G bits 31..24, R bits 23..16, B bits
  15..8, low byte 0**: `(g<<24) | (r<<16) | (b<<8)`. Mirrors pico-sdk's
  "0xGGRRBB00" comment exactly.
- Brightness cap by SCALING channel values (item contract; no library
  brightness API exists to rely on anyway): `scaled = channel *
  RGB_BRIGHTNESS / 255` (truncating — house style). The color map only ever
  writes 0 or 255 per channel → scaled values are exactly 0 or 60.

## 7. Codebase state & anchors (verified this session)

- `config.h` (READ-ONLY, §8 frozen): `USE_ONBOARD_RGB = true` (bool, constexpr)
  and `RGB_BRIGHTNESS = 60` already exist — section "---- 6. LED patterns".
  No config change needed or allowed.
- `jug_filler.ino` UNGUARDED region: `LedPatternEngine` (P1.M5.T1.S1, landed)
  with public `tick(nowMs) -> bool`, `mode() -> Mode` (Off/Solid/DonePulse/
  FaultBlink), `faultGroups()`. Its caller-contract comment already names the
  mirror API: "mirror: color from led.mode(), level from tick()".
- ARDUINO region: T2S1 (parallel, mid-landing) has landed its state block:
  `// ---- External LED driver state (P1.M5.T2.S1) ----` … `static
  LedPatternEngine s_led;` … `// ---- end External LED driver state (used by
  loop, shared with P1.M5.T3.S1) ----` — insert the WS2812 block AFTER this
  banner, BEFORE `void setup()`. The loop LED stage (`const bool ledOn =
  s_led.tick(nowMs); digitalWrite(PIN_LED, ledOn ? HIGH : LOW);`) had NOT
  landed yet at research time — PRP Task 0 verifies it exists (T2S1 contract).
- setup() order (frozen invariants): valve LOW line 1 → … → Serial.begin →
  analogReadResolution → boot banner logLine → **[WS2812 init slots HERE]** →
  `watchdog_enable(...)` LAST (arch boot order).
- Loop stage order (firmware_architecture.md): watchdog → BOOTSEL → ADC →
  **LED drivers (GP14 + WS2812 mirror)** → (P1.M6.T2.S1 inserts fill routing
  ABOVE the LED stage). Mirror lands INSIDE the LED stage, right after the
  `digitalWrite(PIN_LED, ...)` line, reusing the same `ledOn` local and
  `s_led.mode()` — one tick per pass is the engine's frozen caller contract.
- `USE_ONBOARD_RGB` is a `constexpr bool`, NOT a macro → cannot be `#if`'d;
  gate with plain `if (USE_ONBOARD_RGB)` (compiler folds it; dead branch
  eliminated). Precedent: none needed — it's the only legal form.
- Explicit-prototype house rule applies to functions the host-compiled region
  sees; ARDUINO-region static helpers defined BEFORE their callers (state
  block sits above setup()) need no prototypes — same as the landed T2S1/
  BOOTSEL/ADC state blocks (objects + inline code, no forward decls).
- Item contract: LOGIC lives in the ARDUINO region; "Mock: none on device" →
  NO native tests for the mirror (engine patterns already native-tested in
  P1.M5.T1.S1); bench color verification belongs to P1.M7.T2.S1.
- Validation: `pio run -e pico` compile gate; `pio test -e native` regression
  (11 projects, all must stay green); never `pio test -e pico` (no transport).
